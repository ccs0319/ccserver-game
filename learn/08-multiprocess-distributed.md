# 08 · 多进程与分布式（什么时候用、用在哪）

## 你将学到

这是你最关心的问题：**"多进程什么时候用？场景是什么？"** 以及它带来的好处与代价。

---

## 1. 先明确：单进程不是"不够好"，是"起点"

- 一台普通机器、单进程多线程，就能扛**很多**（本框架单机压测约 17 万请求/秒，见 `docs/benchmark.md`）。
- **大多数项目从单进程开始就够。** 不要一开始就上多进程——那是自找复杂度。

## 2. 什么时候必须上多进程（四个"墙"）

你会在下面任意一个"墙"前决定拆：

| 墙 | 症状 | 对策 |
| --- | --- | --- |
| **① CPU 墙** | 单机 CPU 打满 | 加机器 → 把部分服务挪到新节点 |
| **② 连接/带宽墙** | 单机网卡/连接数到顶 | 多开 **gateway**（连接无状态，随便加） |
| **③ 单 actor 墙** | 一个 world 分片处理不过来 | **分片** world_1..N（可同机也可跨机） |
| **④ 故障域墙** | 一台崩全挂 | 多节点 + 故障转移 + 自动注销 |

还有一个软性理由：**独立伸缩/发布**——登录高峰只想扩登录，不想动战斗。

## 3. 多进程怎么工作（回顾第 2、5 篇）

```
node1 (进程A)                          node2 (进程B)
 gateway/login/lobby/world_1            world_2
  ↑ cluster.listen :42345               ↑ cluster.listen :42346
        └────── etcd / 静态注册表（谁在哪）──────┘
```

- 每个进程 = 一个**节点**，有自己的 `node_id`。
- 服务之间照旧 `router.call("world_2", ...)`：
  - 本节点 → 本地调用；
  - 异地 → `cluster.call` 走 TCP，**对业务代码透明**。
- 节点地址由**服务发现**（etcd）提供；节点死了，租约过期，自动从注册表消失。

## 4. 两个最常见的拆分动作

### (a) 网关水平扩展（连接分片）

连接是**无状态**的：谁连上哪个 gateway 就归谁。所以：
- 多开几个 gateway（同机多进程，或不同机器）；
- 前面放一个负载均衡（L4/L7）把客户端连接分下去；
- 会话属主在 Redis，跨网关顶号照样工作。

### (b) 世界分片（有状态拆分）

一个 world actor 是**串行**的，玩家多了就排队。把地图/线路拆成 `world_1..N`：
- gateway 按玩家所在 zone 路由到对应分片；
- 分片可以都在一台机器（单进程多 actor），也可以分散到多台机器；
- 每个分片独立扛一部分玩家 → **总容量 = 分片数 × 单分片容量**。

## 5. 多实例 + 故障转移（服务组）

同一个逻辑服务可以有多实例，框架做**轮询 + 熔断 + 失败转移**：

```lua
groups = { lobby = { "lobby_1", "lobby_2" } }
router.call("lobby", "enter", uid)   -- 轮询到 lobby_1/lobby_2；一个挂了切另一个
```

适合**无状态/弱状态**的服务（lobby）。有状态服务（world）要用"分片"而不是"随便轮询"。

## 6. 代价：多进程不是免费的

| 好处 | 代价 |
| --- | --- |
| 水平扩容 | **网络跳数**增加（跨进程调用比本地慢） |
| 故障隔离 | **不能共享内存** → 共享状态必须外置（Redis/DB） |
| 独立发布 | **运维复杂**（发现、部署、监控更多进程） |
| 容灾 | **一致性**更难（跨进程要处理失败/重试） |

所以：**能单进程就别多进程；到了墙再拆。**

## 7. 决策清单（照着走）

```
1. 单机单进程能扛住吗？      → 能：就用它（最简单）
2. CPU 到顶？               → 加节点，把部分服务挪过去
3. 连接/带宽到顶？           → 多开 gateway（水平扩展）
4. 某类玩家/某区卡？         → 分片（world_1..N）
5. 要求高可用？             → 多节点 + 故障转移 + etcd 自动注销
```

## 记住这句

> **单进程是起点；遇到 CPU/连接/单 actor/故障域四堵墙才拆；网关靠水平扩展、世界靠分片、无状态服务靠多实例+故障转移。**
